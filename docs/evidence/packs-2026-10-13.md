# Domain packs against the baseline, 2026-10-13

This is slice 8 of the [roadmap](../roadmap.md), covering
[ADR-0059](../adr/0059-domain-packs.md) and
[ADR-0060](../adr/0060-subtypes-keep-their-base-protections.md). It is
measured against [`baseline-2026-10-13.md`](baseline-2026-10-13.md), where a
domain existed only as TypeScript code imported and registered at startup.

## What a deployment can now do that it could not

| Before | Now | Shown in |
|---|---|---|
| Receive a domain only as an npm package | One JSON file per domain version, installed offline | `packs.test.ts`: "installed from its files with no network..." |
| Trust a domain by where it came from | A SHA-256 digest and Ed25519 signatures, checked against keys the deployment trusts | "refuses a changed pack, and with trusted keys one no trusted key signed" |
| Find missing code, rules or adapters one failure at a time, at startup or first use | Every missing binding, policy rule, adapter and dependency reported before anything registers | "reports everything a deployment is missing at once, and registers nothing" |
| Fork a domain to add a site's Types | A pack that requires and extends it | "is specialized by a pack that extends it" |
| Guess whether a new domain version breaks what is built on it | The contract diff across everything installed, the version bump it needs, and every dependent's range | "checks an upgrade against the contract diff..." |

## The archive path is the code path

Core and airforce installed from their committed files describe exactly
the model the domain registers from code (`describeModel` equal). The
runtime built over them gives identical answers to the maintainer, the
viewer and an anonymous caller on four reads, refusals included: an object
with provenance, a filter on a computed value, the Actions on one object,
and an Action preview. Hospital installed from its file describes the same
model as its testbed.

| Archive | Size | Types | Actions | Code it names | Policy rules it names |
|---|---|---|---|---|---|
| `core-1.0.0` | 5.4 KB | 6 | 0 | none | none |
| `airforce-1.0.0` | 12.9 KB | 4 | 2 | 2 computed, 2 preconditions | 3 |
| `hospital-1.0.0` | 7.3 KB | 3 | 0 | none | 4 |

## What it costs

These figures come from 200 runs after 20 warm-up runs, on Node 22, over
core and airforce, in two runs.

| Step | p50 | p95 |
|---|---|---|
| Verify both archives (digest, recomputed requirements) | 0.18, 0.19 ms | 0.26, 0.25 ms |
| Plan the install, including the scratch registration | 11.2, 10.8 ms | 17.3, 17.0 ms |
| Read both files and install | 20.6, 21.2 ms | 29.6, 29.3 ms |
| For reference: `buildRuntime` from code (also builds the runtime and policy engine) | 26.7, 26.3 ms | 37.6, 36.6 ms |

The scratch registration roughly doubles registration time, a one-off
cost at startup or install. The reference row does more than register and
is not a like-for-like comparison.

## A core defect found on the way

Specializing by extension exposed a gap in core registration, which
composed a subtype's schema, relationships and computed values but not its
`x-policy` or `x-provenance`. Reproduced on the demo, a `site.F16` that
extends `airforce.Aircraft` and names only `objectPolicy:
airforce.read-aircraft` gave the CUI-cleared viewer three values the
Aircraft itself withholds from them:

- the maintainer-only `maintenanceStatus`;
- the SECRET `deploymentLocation`;
- `readinessStatus`, which is computed from `maintenanceStatus`.

A subtype naming no policy was readable by no one. ADR-0060 fixes it: a
subtype inherits its base's protections and may add to them but not
replace them. No demo or test domain extended a protected Type, so no
existing behavior changed (the full suite passed before and after).

## Mutation check

18 mutations to `@typesys/packs` and 6 to the ADR-0060 fix were made, and
each failed at least one test. ADR-0059 and ADR-0060 list them. One more
packs mutation, which continues the scratch registration after its first
failure, only changes how many diagnostics are reported, not whether the
install is refused. It is equivalent and was not counted.

## Not shown

These are not in this slice:

- Packs carry no workflows and no sample data.
- YAML domains cannot be packed, because they have no data sources or
  mappings.
- There is no pack registry, key revocation or uninstall.
- The Postgres registry store was not exercised with inherited protections
  locally (CI runs it). The composed protections are stored in the schema
  it already persists.
